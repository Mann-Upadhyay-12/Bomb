Start here

One bomb. Two views of the information.

The Defuser operates the live bomb. Helpers open their own module tabs, which can contain a rule list, a lookup table, a different view of the puzzle, or information hidden from the Defuser. Each entry below states what each role actually receives.

This guide covers 36 module types. A bomb may contain a subset of them. The only copy-count assumption is at most one of each module on a bomb; there may still be several Helpers. Every existing module has a corresponding Helper tab except Breaker, The Eye, and Pressure. Rubik’s Cube has a Helper tab and image even though no separate instruction manual is needed.

The illustrated board is a visual table of contents. Its A1–F6 labels identify entries in this guide; they do not prescribe the layout, module counts, or timer length of a bomb. Module rules use the current bomb’s actual serial and counts.

Non-needy modules

A completion to reach

Some need one response; others have stages, a sequence of moves, or a board to clear. An intermediate stage is progress toward disarm. It does not add a disarmed module to a count.

Six needy types

A condition to maintain

Breaker, The Eye, Pressure, Knobs, Laundry, and Bluescreen impose recurring or event-triggered conditions while the bomb is active. Handling one occurrence does not turn a needy module into a disarmed non-needy module.

Use the matching bomb, hand, load, or stage.

Highlighted values, word lists, codes, tables, and most images may vary between bombs or during a run. Numerical examples below are labeled. The Laundry symbol image is a fixed legend. The index portraits identify module types; each Helper example belongs to its own puzzle and need not match its portrait.

Live state

Simon Says and Knobs use the number of non-needy modules currently disarmed. Another module’s completion can change the applicable rule.

Captured state

Laundry uses the counts captured for its current load. Bluescreen uses the bomb state at its crash. Later progress must not replace either snapshot while interpreting that same load or error.

Bomb-wide reference

Batteries constrain completion.

Defuser sees

Bomb Info contains the serial number and battery inventory. The Defuser describes the battery types and quantities to the Helpers. PBT0EF21 is the supplied example serial.

Helper sees

A separate Batteries tab contains the condition chart and its rule legend. The Helper needs the Defuser’s inventory to decide which chart rows apply.

Every matching row applies. Disarming a module against any matching row detonates the bomb. A digit in a module’s cell must appear somewhere on the displayed timer at the moment of disarm. ANY and an empty cell add no restriction for that row; neither cancels a restriction from another matching row. A FIRST–THEN arrow requires FIRST to be disarmed before THEN.

Order

Prerequisites can combine across rows. If A must precede B and B must precede C, A also precedes C. These are final-disarm restrictions, distinct from simply reading or preparing a module.

Displayed digits

A requirement for 2 can be met at 2:xx, x:2x, or x:x2. If matching rows require both 0 and 4, a display such as 4:00 contains both. These are timer-display conditions, not instructions to wait a fixed number of seconds.

The chart, inventory, and module names must belong to the same bomb. Its restrictions remain independent of the Eye’s permission, the Breaker’s state, and a module’s own completion rule.

Needy modules

Recurring controls that keep affecting the bomb after a single interaction.

Index C1Needy

Breaker

Keep the power switch ON whenever answering another module.

#

Defuser sees

The current ON/OFF state and a Flip control. The supplied tab explicitly reports the state in text.

Helper sees

No Breaker tab. Helpers learn its current state through the Defuser or a shared observation.

How it works

Every 30 seconds, the Breaker has a 50% chance to trip itself OFF. Flip toggles its state, so pressing it while already ON turns it OFF. The Breaker must be ON before the Defuser answers any other module; answering another module while it is OFF detonates the bomb.

Progress and changing information

Breaker is needy. Turning it ON handles the present condition but does not permanently complete the module or prevent later trips. The 30-second check is an opportunity to trip, not a guaranteed toggle at every check.

Rule note

The stated failure condition concerns answering another module while the Breaker is OFF. The tab does not describe a separate OFF-only countdown.

Sources Defuser instructions / Helper manual
Index A3Needy

The Eye

A recurring permission rule determines which module may receive answers while the Eye is open.

#

Defuser sees

The Defuser sees whether the Eye is open or closed and, when open, the name of its prescribed module.

Helper sees

Helpers have no Eye tab. They learn its current state and prescription from the Defuser.

How it works

Every 30 seconds the Eye can be open or closed. When open, it names the permitted module; submitting an answer to another restricted module detonates the bomb. When closed, it imposes no Eye restriction. A closed Eye does not cancel the Breaker requirement, Batteries restrictions, or a module’s own rules. Looking at a module and discussing an answer are distinct from submitting that answer to the game.

Progress and changing information

The current permission follows the live Eye and governs intermediate non-needy answers as well as the final answer that disarms a module. Needy maintenance, such as releasing Pressure, flipping Breaker, and adjusting a knob, is exempt. Completing the prescribed module resets the prescription early without moving the next regular 30-second checkpoint.

Index D6Needy

Pressure

Release pressure exactly once during each fixed 30-second window.

#

Defuser sees

The Release Pressure control and the instruction to use it once per 30-second window. There is no visual indicator showing whether the required release has been performed.

Helper sees

No corresponding Helper tab. Helpers can still coordinate timing and record the Defuser’s confirmed releases, but they have no separate Pressure manual or hidden indicator.

How it works

The running bomb is divided into fixed windows such as 0–30 seconds and 30–60 seconds of elapsed time. One release satisfies the current window. It does not start a fresh 30-second allowance or move the next boundary. Missing a window or releasing twice within one window detonates the bomb.

Progress and changing information

The relevant state is elapsed bomb time and whether the current window has already received its one release. Pressure stays needy throughout the run rather than becoming permanently solved after a click.

Index E5Needy

Knobs

Match two six-light patterns to directions, then choose between them using the current disarmed-count parity.

#

Defuser sees

A knob pointing UP, DOWN, LEFT or RIGHT, plus twelve lights arranged as two rows of six. The Defuser changes the knob’s direction.

Helper sees

The current direction-to-pattern manual. It groups possible six-light rows under UP, DOWN, LEFT and RIGHT; X means lit and O means off. The Helper needs the Defuser’s actual top and bottom rows and the current number of disarmed non-needy modules.

How it works

Each of the two light rows matches a pattern under a direction in the Helper’s manual. The disarmed non-needy count then chooses which row’s direction applies: an odd count chooses the row with more lit lights, while an even count, including zero, chooses the row with fewer. The number of lit lights chooses the row; the pattern’s placement in the manual supplies the actual knob direction.

Progress and changing information

Every 60 seconds both the lights and the Helper manual change. A pattern read from one interval must be matched against that interval’s manual. Completing another non-needy module can change the applicable odd/even choice even while the light patterns stay the same. Knobs remains needy; satisfying one check is not a permanent disarm. An incorrect direction at a 60-second check detonates the bomb.

Example from the supplied tab

In the supplied manual, XXOXOO belongs to UP and has three lit lights; XXOOOO belongs to DOWN and has two. If these were the two displayed rows, an odd disarmed count would select UP and an even count would select DOWN.

Rule note

The supplied rules do not specify how to choose between rows with equal numbers of lit lights when their matched directions differ.

Index B2Needy

Laundry

At each 60-second check, four care settings must match a load derived from captured bomb counts.

#

Defuser sees

Four icon controls: Wash and Dry on the top row, Iron and Special care below. The tab also reports the load number, its captured remaining/solved/needy/total counts, the serial, and a check-time status.

Helper sees

The current load’s calculation instructions, item/material/color tables, exception rules, and the care-symbol legend. The supplied legend image is fixed across bombs; the load’s text values and tables must still be read from its current manual.

How it works

The load is calculated from captured counts rather than silently replacing them with the bomb’s later live counts. Three formulas identify an item, material, and color after repeatedly subtracting six to reduce each result to 0–5. The item supplies Iron and an item-care option; material supplies Wash and material care; color supplies Dry and color care. Then the stated overrides apply: Leather or Jade Cluster sets Wash to 30°C, and Wool or Star Lemon Quartz sets Dry to High heat. Special care uses only the first matching condition: Clouded Pearl chooses Non-chlorine bleach; Corset or Corduroy chooses material care; a material sharing a letter with the serial chooses color care; otherwise use item care.

Progress and changing information

Laundry is checked every 60 seconds, and wrong settings explode. Reopen the Helper tab for every new load. The static icon legend explains what the displayed care symbols mean; it is not the variable load calculation. The controls cycle through their settings; the displayed icons identify the settings currently selected.

Example from the supplied tab

The example formulas use Item = remaining + 1, Material = solved + needy + 2, and Color = last serial digit + total + 2, using zero if the serial has no digit. Apply them to the counts captured for the load, then reduce each result as the manual instructs. The offsets are example values; another bomb or load can supply different values.

Rule note

The supplied text reduces the indices to 0–5 but displays the six category lists numbered 1–6. It does not explicitly align those two indexing conventions. This guide explains the calculation without silently inventing a residue-to-list-row mapping.

Index F4Needy

Bluescreen

A crash code identifies an already-disarmed module that must be power-cycled within 60 seconds.

#

Defuser sees

The Defuser sees the crash error number and can open a disarmed module to press Power Cycle. Every 60 seconds Bluescreen has a 25% chance to crash.

Helper sees

The Helper sees the arithmetic and reading-order rules for turning the four-digit error into a target. The Helper needs the error, serial, and armed/disarmed board state as they were when the crash occurred.

How it works

A crash starts a 60-second response deadline. The required action is Power Cycle on the particular module selected by the error. That target must be one of the non-needy modules already disarmed at the crash. Power-cycling any other module, or missing the deadline, detonates. Needy modules and the Timer are excluded from both the armed and disarmed counts.

How the error selects a target

Start with the sum of the four error digits. If the armed count is even, add the first digit; otherwise subtract the last digit. Also add 4 if the serial contains a vowel, subtract 2 if its last digit is odd, and add the third error digit if disarmed modules outnumber armed modules. Every applicable adjustment is included. Count the result through the disarmed modules in reading order, left to right and then top to bottom, skipping armed modules and wrapping after the last disarmed one. If the adjusted total is zero or negative, add the number of disarmed modules repeatedly until it is positive.

Progress and changing information

All quantities in that calculation belong to the crash snapshot. Later disarms do not change the target for an existing crash. A fresh crash has its own code, snapshot, and deadline. The 60-second crash check is probabilistic; the separate 60-second response deadline begins when a crash actually occurs.

Rule note

The supplied rule does not define a crash with no disarmed modules, or explicitly settle whether final bomb completion ends an already-active crash deadline.

Stages and sequences

Each successful response advances the module, and some answers depend on earlier stages.

Index E1Non-needy5 stages

Logic

Combine Defuser-only expressions with Helper-only variable assignments across five dependent stages.

#

Defuser sees

The current stage expression, the stage number out of five, and True/False answer controls.

Helper sees

The truth assignments for P, Q, R, S, and T; operator definitions; and the mapping from earlier stage answers to α, β, γ, and δ. The Helper obtains each expression from the Defuser.

How it works

Evaluate the current expression using this bomb’s assignments. NOT reverses a truth value; AND requires both sides true; OR requires at least one side true. Implication is false only when its left side is true and its right side false. Parentheses specify grouping. The variable named T is distinct from using T as an abbreviation for a truth value.

Progress and changing information

There are five stages. The first four answers become α, β, γ, and δ respectively in later expressions. The expression changes with the stage, while the Helper’s assignments and recorded earlier answers supply the interpretation. Completing all five stages finishes the module.

Example from the supplied tab

The example assignments are P=true, Q=false, R=true, S=false, and T=true. With those assignments, P ⇒ Q is false. These values illustrate evaluation and are not permanent assignments for every bomb.

Index E2Non-needy5 stages

Memory

Use a Helper-only stage rule together with current buttons and a history of both positions and labels.

#

Defuser sees

The large display number, four numbered buttons in left-to-right order, and the current stage out of five.

Helper sees

A text rule for each stage/display combination. The Helper needs the Defuser’s display number and all four current button labels to translate the rule into a position to press.

How it works

A rule may identify a numbered position, a printed label, a position used on an earlier stage, or a label used on an earlier stage. These are different instructions. Positions are counted left to right, while labels move with the changing button arrangements. A label-based rule must be translated using the current arrangement before it identifies the physical button.

Progress and changing information

There are five stages. Each successful press adds a position-and-label record that later rules can reference. The current display and four labels change with the stage; the earlier pressed label and position remain historical facts. Completing all five stages finishes the module. A wrong press detonates the bomb.

Example from the supplied tab

For display 1 in stage 1, the supplied manual says to press the button labeled 4, wherever that label is. For display 3 in stage 2, it instead asks for the same position used in stage 1. For display 4 in stage 2, it asks for the same label used in stage 1. These three rules illustrate why both pieces of history matter.

Rule note

The example’s twenty rules belong to its bomb. The mechanism is stable, but the particular display-to-instruction table must come from the current Helper tab.

Index D4Non-needy5 stages

Simon Says

Translate the Defuser’s flash sequence through a table selected by the serial and the current disarmed-module count.

#

Defuser sees

The Defuser sees the colored flashes, the four colored controls, and the current stage out of five, then enters the response sequence.

Helper sees

The Helper sees the color-translation table. Its rows distinguish serials with or without a vowel and odd or even counts of currently disarmed non-needy modules.

How it works

Choose the applicable table row from the serial and the current disarmed non-needy count. Within that row, each flashed color selects the color that must be pressed. Translate the sequence in its original temporal order, including repeated colors as separate flashes. The response can differ from the observed flashes because the table supplies a substitution.

Progress and changing information

There are five stages. The flash sequence changes with progress, and another module’s disarm can change the odd/even row while Simon is being handled. The count is current, not a frozen value captured at the beginning of the bomb. Needy modules are excluded. The applicable mapping must be used for each position in the sequence. An incorrect press detonates the bomb.

Example from the supplied tab

The example serial PBT0EF21 contains E. With zero disarmed non-needy modules, the sample table therefore uses its Vowel / Even disarmed row; in that row a blue flash maps to a yellow press. The color mapping is an example from this supplied table, not a universal mapping.

Index C5Non-needy5 stages

Wire Sequences

Across five panels, each wire is judged by its color’s occurrence number and the letter it connects to.

#

Defuser sees

The current panel’s wires, their colors and connections, the current stage, wire-cut controls, and Next Panel. The displayed wire positions identify which physical wire will be cut.

Helper sees

A table with separate red, blue and black columns. Each column lists permitted destination letters for the first, second, third and later occurrences of that color; the supplied image has rows through the ninth occurrence.

How it works

Count each color separately across the entire module, keeping the panel order and reading the wires on a panel from top to bottom. A wire is cut exactly when its destination letter appears in the table entry for that color and occurrence number. Every encountered wire advances its color’s count, whether it is cut or left intact. A panel can therefore require several cuts or no cuts. Once that panel is complete, Next Panel advances to the next one.

Progress and changing information

The module has five stages. Color counts carry across panel boundaries and are not reset by Next Panel. Finishing the fifth panel disarms the module. Cutting a wire that should remain, or advancing while a required cut is missing, detonates the bomb. A wire’s physical position, its connector letter, and its color-occurrence number are three distinct identifiers.

Example from the supplied tab

In the supplied table, the first red wire is cut only for A or C. If that first red wire ends at B, it is left intact but still counts as the first red. The next red wire uses the second-red entry, B or C, even if it appears on a later panel.

The Button

Use an ordered rule list to determine the interval between two presses, over three stages.

#

Defuser sees

The Defuser sees the button’s physical color, printed label, and stage indicator. Pressing once starts the timer; pressing again stops it.

Helper sees

The Helper sees the ordered condition-and-duration rules and combines the Defuser’s button description with any required serial or module-count information.

How it works

Read the rules from the top and use the first matching condition. That rule supplies the required interval between the first and second presses. The button’s physical color and printed word are separate inputs: the word White can appear on a green button, and the label Hold does not change the two-press control into a continuous physical hold. The first press starts the game’s timer; the second ends the measured interval.

Progress and changing information

There are three stages. Each new button must be evaluated against the rules using its current color and label. Under this guide’s assumption of at most one copy of each module, a condition requiring more than one Button module cannot match. Other count-dependent rules still use the actual bomb’s total and needy counts.

Example from the supplied tab

For the supplied example rules, a green button labeled White selects the first rule and a five-second interval. A later rule about a color word differing from the physical color also fits, but the earlier matching rule controls. The durations belong to the current manual.

Index A6Non-needy3 stages

Piano

Translate the pitch interval between two written notes into the current Helper table’s entry code.

#

Defuser sees

Two notes on a staff, the current stage and a stated key signature. The supplied Defuser example says D♭ Major. The Defuser reads the notes and enters the code returned by Helpers.

Helper sees

A table assigning codes to musical intervals from minor second through octave, including the tritone. The supplied Helper tab gives the interval codes but not the Defuser’s staff or key signature.

How it works

The notes’ pitches depend on their clef, staff positions, key signature and written accidentals. The interval is measured upward in half-steps from the lower pitch to the higher, regardless of which note is drawn farther left. The Helper identifies the interval name and supplies that interval’s code from the current table. The code, rather than the note names or interval name, is the game-side response.

Progress and changing information

There are three stages. Each stage needs its current notes, key signature and corresponding code table; a code from an earlier stage is not a universal code for the same interval. Completing all three stages disarms the module. A wrong interval code detonates the bomb.

Example from the supplied tab

In the supplied table, a perfect fifth maps to 7.72 and an octave to 2.22. The D♭ Major key belongs to the Defuser’s supplied stage; it does not by itself identify which of those intervals is shown.

Index A5Non-needy3 stages

Who’s on First

A two-step text lookup turns a display word into a reference position, then a priority list of button labels.

#

Defuser sees

The green display text and six button labels in two columns of three, together with the current stage and the controls to press those buttons.

Helper sees

Two text references: display words grouped by the six possible reference positions, and a separate ordered list for each possible reference-button label. The Helper does not receive the Defuser’s current display or six-button arrangement in this tab.

How it works

First, the display word selects a position in the Helper’s first table. The Defuser reads the label on the button at that position. That label selects a list in the second table. The answer is the first entry in that list that appears anywhere among the six current buttons. The reference button is an information source; it need not be the button eventually pressed. Spelling, punctuation and actual absence of text matter: WHAT and WHAT? are different labels, and a truly blank display differs from the printed word BLANK.

Progress and changing information

There are three stages. A correct press advances to the next display and button arrangement; completing all three disarms the module. Each stage uses its own current arrangement. A wrong button press detonates the bomb.

Example from the supplied tab

In the supplied first table, a display reading C points to the top-left button. If that reference button reads PRESS, the applicable priority list begins WHAT, MIDDLE LEFT, DON’T, IDK. The button to press depends on which of those labels actually appears among the six buttons, not on the reference position alone.

Index B3Non-needy3 stages

Search

Find the single word shared by the Defuser’s letter grid and the Helper’s current candidate list.

#

Defuser sees

The Defuser sees the letter grid, the current stage out of three, and the control for entering a word.

Helper sees

The Helper sees a list of candidate words for the current stage and needs the Defuser’s grid to locate the match.

How it works

Exactly one word from the Helper’s current list appears in the Defuser’s grid. The listed word can run in any direction; the established grid-reading model includes horizontal, vertical, and diagonal straight lines in both directions. The submitted response is the word itself. Other readable dictionary words in the grid do not become valid answers merely because they are words.

Progress and changing information

There are three stages. The grid and candidate list must refer to the same current stage, and completing all three stages disarms the module. A wrong submitted word detonates the bomb. The possible answers come from the current Helper list.

Example from the supplied tab

EPIC, BATH, HARP, and WORN are entries in the supplied sample list. The instruction guarantees one match from the full list; the list alone does not identify which one because the Defuser’s grid supplies the other half of the information.

Words, signals and symbols

Identify a word, symbol or signal by combining the two roles’ information.

Index A1Non-needy

Astrology

A Defuser-only star count and four symbols are interpreted through the Helper’s constellation list and sky map.

#

Defuser sees

A star display and four numbered symbol buttons. The Defuser counts the stars, describes the symbols, and operates the chosen button.

Helper sees

This bomb’s constellation-by-star-count list and a sky map divided into four quadrants. The Helper does not receive the Defuser’s star display or numbered button arrangement in the supplied tab.

How it works

The star count selects every constellation with that many stars in the Helper’s list. The Helper locates those constellations on the sky map, then compares their quadrants with the locations of the four button symbols. Exactly one button’s symbol shares a quadrant with at least one of the selected constellations. The response is that numbered button, and a wrong button detonates the bomb. The displayed star drawing is used for its count; its outline is not itself the matching rule.

Progress and changing information

The star display, button symbols, constellation assignments, and sky map belong to the current bomb. A map or table from another bomb is not a substitute, even if the same star count appears.

Example from the supplied tab

For a screen containing three stars, this example list selects Chamaeleon, Corona Australis, Orion, and Piscis Austrinus. Their map quadrants are the relevant comparison; those names are not words that the Defuser enters.

Hangman

Identify a hidden word while every letter guess, including a correct one, advances the stick figure.

#

Defuser sees

How it works

Each stage requires exactly one queen in every row, every column, and every colored region. Queens may not touch at an edge or a corner, so diagonally adjacent queens are forbidden. Reference

Terms used in this guide

Position versus label
A position tells where a control is. A label tells what is printed on it. Memory and Who’s on First use both with different meanings.
Observation versus submission
The color found in Limbo leads to a frequency to enter. A decoded Morse word also leads to a frequency. The intermediate observation is not always the submitted answer.
Last serial digit
The rightmost numerical digit in the serial, even when letters follow it. The documented vowel tests use A, E, I, O and U.
Stage versus reading
A stage is progress after a response. A reading is observed information. Password’s scrolling rows are letter choices, not separate disarm stages.
Live count versus captured count
Simon and Knobs use current disarmed counts. Laundry uses the counts printed for the load; Bluescreen uses the state when the crash occurred.
One module versus one Helper
The guide assumes at most one copy of a module per bomb. Multiple Helpers can still have distinct manuals, and Symbols explicitly combines their counts.
Index position versus game coordinate
A1–F6 locates entries in this guide’s illustrated index. The actual bomb layout and each module’s internal grid have their own coordinates. Battleship links each shot cell to the bomb slot in the same position on the live bomb.
Power cycle versus offline
Bluescreen requests a power cycle of an already-disarmed target. A Battleship shot disables its slot for 20 seconds. These are separate effects.
Scope and sources

About this guide

This guide explains the mechanics of 36 module types and the information available to each role. It assumes at most one copy of each module on a bomb. The illustrated index provides navigation; it does not specify a bomb’s composition, layout, or timer length.
